# Slidev で登壇資料を作る

Slidev は「指定したのに効かない」箇所が多い。**変更したら必ずレンダリングして目で確かめる。**
推測で積み上げると、あとでまとめて崩れる。

作業を始める前に `references/constraints.md` を読む。実測済みの制約がまとまっている。
この repo の構成（どのテーマを触ってよいか）は `references/repo-layout.md`。

## 0. 会場の要件を先に確認する

登壇先のガイダンスに**デッキの作り方を縛る条件**が書かれていることが多い。着手前に読む。
Vue Fes Japan 2026 の例（[ガイダンス](https://esa-pages.io/p/sharing/6906/posts/2077/948ee02ce0da5ab939a1.html)）:

| 条件 | デッキ側への影響 |
|---|---|
| **ライトモード推奨**（ダークはプロジェクターでコントラストが落ちる） | 白地のテーマで作る。既存のダークテーマを流用しない |
| 解像度 1920×1080 / 16:9 | Slidev の既定（980×551・16:9）と一致。export もこの比で出る |
| **バックアップを PDF で事前提出**（`.key` / `.pptx` は環境で崩れる） | `slidev export` で PDF を出す。締切があるので早めに一度通す |
| フルスクリーン表示 | OS や dev サーバーの UI が映らないようにする |
| 参加者800名以上 | 後方席から読める字にする。最小フォントを妥協しない |

こうした条件は**デッキの根っこを決める**。白地にするかダークにするかは、あとから変えると
テーマ・アイコン・図の配色まで全部やり直しになる。

## 1. デッキを置く

**リポジトリ直下に `.md` を置く。** Slidev はエントリ `.md` のあるディレクトリを user root にするため、
`decks/` などサブディレクトリに入れると `components/` `setup/` `theme: ./xxx` の解決が壊れる。

`package.json` にはデッキ別の script を**追記だけ**する（既存は触らない）:

```json
"dev:<name>":    "slidev <file>.md --open",
"build:<name>":  "slidev build <file>.md --out dist/<name>",
"export:<name>": "slidev export <file>.md --output <file>.pdf"
```

`--out dist/<name>` は、デプロイ設定が使う `dist/` と衝突させないため。

## 2. 1枚に載せる量

- **1枚1論点。本文は120字以内**（コードと図の文字は除く）
- 削った説明は**必ず発表者ノート `<!-- -->` へ退避**する。全スライドにノートを入れる
- アウトラインの箇条書きをそのまま並べない。第2階層以下は基本ノート行き
- 体言止めにすると一気に減る（「〜が明確になった」→「〜への要求」）

字数は測れる:

```bash
python3 .claude/skills/slidev-talk-deck/scripts/slide-stats.py <file>.md
```

## 3. 文字とコードの大きさ

- **最小フォントは20px。** UnoCSS の `text-sm`(14) / `text-base`(16) / `text-lg`(18) は下回るので、
  テーマ側で床を敷く
- **コード例は本文より大きく。** 用途で3段階に分ける。スライド単位の指定は
  **frontmatter の `class:`**（`.slidev-layout` に付く）で行う。ラッパー div では届かない

| 用途 | クラス | 目安 |
|---|---|---|
| 構文そのものを読ませる1枚 | `code-hero` | 32px |
| 全幅のコード | （既定） | 30px |
| 2カラムの比較 | `code-compact` | 21px（幅386pxに30桁） |

## 4. 段階的に見せる

構文の説明は紙芝居にすると伝わる。shiki の行ハイライトと `v-click` は**クリック番号を共有する**:

````md
```astro {*|1-4|5}
---
const price = 1200;
---
<p>{price}</p>
```

<v-click at="1"><div>Component script — <code>---</code> で囲む</div></v-click>
<v-click at="2"><div>Template — HTML を基礎に式を書ける</div></v-click>
````

確認は `--with-clicks` を付けて export する（1クリック1枚で出る）。

## 5. アイコンとロゴ

- コレクションは**明示的にインストール**する（Slidev は `autoInstall` していない）
- **寸法の指定方法を形で使い分ける。** ここは間違えても気づきにくい:
  - 正方形に近いシンボル → `text-*`
  - 横長のワードマーク → `w-* h-*` の**両方**
  - `<img>` のロゴ → `h-*` だけでよい

理由は `references/constraints.md` に書いてある。`h-*` だけ指定しても絵が大きくならないのが既定動作。

## 6. 検証（毎回まわす）

```bash
# 全枚を出力して、下端にはみ出しているスライドを機械検出する
bash .claude/skills/slidev-talk-deck/scripts/check-overflow.sh <file>.md

# 既存デッキの回帰も見る（共有ファイルを触ったとき）
npx slidev build
```

はみ出しは目視で追わない。上のスクリプトが枚数を問わず一定時間で出す。

出力した PNG は**実際に開いて見る**。検出できるのは「下端をはみ出した」だけで、
横の食い込みとアイコンが潰れていることと字が小さすぎることは、目で見ないと分からない。

## 7. 文言の検査

AI が書いたような語と記号を機械で見つける。

```bash
npm run lint:text
```

`references/forbidden-terms.txt`（72語）と `references/discouraged-symbols.txt` を
literal 一致で探す。出どころは `~/.codex/skills/avoid-ai-cliches-ja` で、
環境に依存させないためこのリポジトリへ写してある。

- **記号の表から `→` は外してある。** この deck では図の中で処理の向きを表すため。
  `「」` と `—` は残してあるので、文章で使えば検出される
- **表にコメント行を足さない。** 空でない行はそのまま検査語として読まれる
- **単語境界を見ない。** `共通する` は `通す` に当たるなど、ふつうの語でも引っかかる。
  当たったら語を置き換えるのではなく、文ごと書き直す

textlint（`~/Downloads/architecture` にある方）はこの deck には使えない。
ルールが `Syntax.Str` しか見ないため、本文の `<div>` と発表者ノートの `<!-- -->` を
読み飛ばす。実測で244件のうち AI 臭を見るルールは7件しか当たらず、残りは frontmatter 由来の
ASCII コロン誤検出だった。
